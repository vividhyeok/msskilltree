# Magic Survival Companion V3 — 추가 피드백 반영 지시서

이 문서는 기존 `CODEX_META_V3_PROMPT.md`를 대체하지 않는다.

**기존 V3 작업 방향을 그대로 유지하면서, 아래 UX/게임 상태 표현 피드백을 추가로 반영해줘.**

핵심은 새 기능을 많이 넣는 것이 아니라, 이미 계산하고 있는 게임 상태를 사용자가 **읽지 않아도 바로 알아볼 수 있게 시각적으로 표현하는 것**이다.

---

## 1. 기존 방향 유지

계속 유지할 것:

- deterministic engine
- Community Meta Layer
- data-driven 구조
- patch/context/confidence/source 기반 meta
- 태블릿 live-play UX
- `NEED NOW` / 현재 목표 / 현재 선택 우선
- 게임 중에는 대시보드/백과사전처럼 보이지 않게
- 구현 세부는 현재 코드베이스를 읽고 직접 판단

---

## 2. 조합 후 “남는 마법”과 “소멸되는 마법”을 구분

Magic Survival의 일반 조합에서 두 마법은 같은 역할이 아니다.

- 하나는 조합의 **주체 / 승계되는 마법**
- 다른 하나는 조합에 **병합되어 소멸되는 재료 마법**

사용자가 느끼길 원하는 감각은:

> 한쪽은 살아남아서 조합 마법으로 이어지고,
> 다른 한쪽은 그 마법에 병합돼 사라지는 느낌.

현재처럼 둘을 모두 단순히 `조합됨`, `사용됨`, `locked`로만 보이면 안 된다.

---

## 3. 역할을 data model에서 명시

현재 데이터에 `primary/material/role` 정보가 있다면 활용하고,
부족하면 일반적인 구조로 확장한다.

개념 예시:

```ts
type CombinationParticipantRole =
  | "carrier"   // 조합 후 승계/변환되는 주체
  | "material"  // 병합되어 소멸
  | "condition" // 패시브/선행조합 등
```

필드명은 현재 코드 스타일에 맞게 정해도 된다.

중요한 것은:

- UI가 어느 마법이 남는지 안다.
- 어느 마법이 소멸하는지 안다.
- condition을 material과 혼동하지 않는다.
- 조합별 if문으로 하드코딩하지 않는다.

---

## 4. 조합 전부터 역할이 보여야 한다

목표 조합이나 경로를 볼 때부터:

```text
데몬 방정식

→ 화염구 / 대폭발
× 에너지탄 / 플레어
```

처럼 어느 쪽이 승계되고 어느 쪽이 재료인지 바로 보여준다.

정확한 아이콘/레이아웃은 직접 결정하되, 긴 설명을 읽지 않아도 구분되어야 한다.

---

## 5. 조합 완료 후 상태도 다르게 표현

### carrier / 승계

회색으로 죽은 카드처럼 처리하지 않는다.

예:

```text
화염구
→ 데몬 방정식으로 변환됨
```

즉 단순 사용 불가가 아니라 **조합 마법으로 이어진 상태**라는 느낌을 준다.

### material / 재료

예:

```text
에너지탄
× 데몬 방정식에 병합됨
```

그리고:

- 더 이상 레벨업 불가
- 다시 목표 재료로 사용 불가
- 다른 조합 가능성에서도 제거
- `+` 버튼 제거/비활성화

기존 deterministic lock logic과 일치해야 한다.

---

## 6. “다시 못 찍는다”는 상태를 즉시 이해 가능하게

재료 마법이 소멸된 뒤에는 일반 미보유/미성장 카드처럼 보여선 안 된다.

`병합됨`, `소멸`, 조합 badge, 아이콘/형태 등으로 **왜 못 누르는지** 바로 이해하게 한다.

---

## 7. 현재 UI는 색을 너무 적게 쓴다

이번 수정에서는 색을 장식이 아니라 **상태 전달 수단**으로 사용한다.

목표:

> 사용자가 텍스트를 읽기 전에 색과 형태로 상태를 먼저 이해한다.

무작정 화려하게 만들지는 않는다.

---

## 8. Semantic Color System

정확한 색상값은 현재 theme/accessibility를 보고 직접 결정한다.

다만 다음 의미들은 시각적으로 구분되어야 한다.

- Target A / B / C → 서로 다른 고유색
- NEED NOW → 가장 강한 attention color
- READY → positive color
- BLOCKED / 충돌 → danger color
- carrier / 승계 → 활성·진행·변환 느낌
- material / 병합 → 소멸·비활성 느낌
- focus → 별도 indicator
- neutral → 낮은 강조

---

## 9. A/B/C는 색으로도 구분

현재처럼 badge 글자만 읽게 하지 않는다.

예:

```text
A = 색상 1
B = 색상 2
C = 색상 3
```

같은 목표에 속한:

- 조합
- Magic Tile
- NEED NOW
- 완료 후 carrier 연결 표시

가 같은 visual language를 공유하도록 한다.

사용자가 반복 플레이하면서:

> 이 색의 마법 둘은 같은 목표 조합이다.

를 바로 인식하게 한다.

---

## 10. 색만으로 의미를 전달하지는 말 것

색각 이상이나 낮은 밝기 환경을 고려해서 중요한 상태는:

```text
색 + 아이콘/형태/짧은 텍스트
```

중 최소 2개 단서로 표현한다.

예:

```text
→ 승계
× 병합
✓ 준비
! 충돌
```

정확한 기호는 자유롭게 정해도 된다.

---

## 11. 화면 전체가 같은 시각 언어를 사용

Target A의 색/형태가 있다면:

- Target panel
- Magic Tile badge
- NEED NOW
- 조합 경로
- 완료 후 상태

에서 일관되게 사용한다.

색이 decoration이 아니라 **관계선** 역할을 하게 한다.

---

## 12. 이 정보는 Meta Layer와도 연결 가능하게

carrier / material 구분은 단순 UI 효과로 끝내지 않는다.

향후 meta engine에서:

- 소멸한 material 마법 전용 Artifact 가치 감소
- carrier/조합 주체 강화 Artifact 가치 유지 여부
- 조합 이후 원본 마법 관련 효과 유지/비유지

를 판단하는 데 쓸 수 있도록 구조를 남긴다.

이번 pass에서 모든 Artifact interaction까지 구현할 필요는 없다.

---

## 13. UI 개선 합격 기준

다음 질문에 YES여야 한다.

> 게임 중 태블릿을 1초 봤을 때,
> 어떤 마법이 어느 목표에 속하는지,
> 무엇이 조합 후 남고,
> 무엇이 사라졌고,
> 지금 무엇을 집어야 하는지가
> 텍스트를 길게 읽지 않아도 보이는가?

---

## 14. 기존 V3 작업을 계속 진행

이 추가 지시 때문에 기존 Meta V3 범위를 좁히지 않는다.

계속 진행할 것:

- Community Meta Layer
- goal/archetype/phase/context 기반 추천
- deterministic / meta 분리
- Artifact/Synergy 확장 가능한 구조
- patch freshness
- tablet live-play UX
- NEED NOW 강화
- player level / 성장 예산 등 실제 판단 개선 요소 검토

이번 피드백은 그 위에 얹는 **상태 표현 디자인 원칙**이다.

---

## 15. 구현 세부는 직접 결정

색상값, CSS, 컴포넌트 구조, 아이콘, 상태명, animation, schema field 명은 현재 코드와 디자인을 보고 직접 결정한다.

이 문서는 구현을 미세하게 통제하려는 게 아니라,
**사용자가 원하는 게임 경험과 구분되어야 할 상태 의미를 전달하는 추가 요구사항**이다.

---

## 최종 목표

현재 앱은 이미 “조합 실수를 줄이는 도구”로 도움이 된다.

이번 V3에서는:

> 조합을 기억하지 않아도 되고,
> 현재 상태를 읽지 않아도 눈으로 파악되고,
> 커뮤니티 메타까지 활용해 혼자 플레이할 때보다 더 좋은 결정을 하게 해주는 Companion

으로 발전시켜줘.

기능 수보다 **판단 속도와 상태 인지 속도**를 우선한다.
